● La definición de historias (EP01, EP02, EP07-EP11, EP15) y las pruebas de aceptación en Gherkin mostraron una buena alineación con los flujos reales de negocio (proyectos, equipo, invitaciones, cambios). Entrevistas o validaciones futuras deberían refinar casos borde (permisos, estados) para mantener la cobertura centrada en lo que más valor aporta.  
● La arquitectura de microservicios con Spring Boot/Spring Cloud brinda independencia por dominio (usuarios, organizaciones, proyectos, cambios), facilitando iteraciones y despliegues sin bloquear a otros equipos. Esta flexibilidad requiere disciplina en contratos de API, gestión de versiones y gobernanza de configuración.  
● El API Gateway unifica seguridad JWT y CORS, y mejora observabilidad; sin embargo, es un punto único de fallo y debe monitorearse de cerca. Versionar rutas y documentarlas evita fricción con frontend y con integraciones externas.  
● Eureka habilita descubrimiento dinámico, pero en entornos gestionados (Azure) puede simplificarse con DNS internos o configuración estática para reducir complejidad operativa. Evaluar si el costo/beneficio de mantener Eureka compensa frente a un esquema más estático.  
● El patrón “DB por servicio” (MySQL) protege la autonomía de datos y minimiza acoplamiento. Recomendación: vigilar costos y rendimiento, ajustar tamaños según carga real y habilitar backups/alertas por servicio.  
● RabbitMQ aparece sólo en invitaciones; conviene decidir si se consolida un bus de eventos transversal o se retira donde no aporte. Reducir tecnologías innecesarias baja la huella operativa y simplifica el soporte.  
● La documentación C3 (diagramas y descripciones) y las features en Gherkin son activos clave de alineación; deben mantenerse versionadas junto con el código para evitar brechas entre diseño, implementación y QA.  
● Para Azure Container Apps: usar servicios gestionados (MySQL, broker) y exponer únicamente el gateway. Esto reduce mantenimiento, mejora seguridad y controla costos. Evitar desplegar bases o brokers stateful como Container Apps.  
● Seguridad: rotar y guardar secretos (JWT, credenciales DB, tokens de registry) en un vault. Revisar políticas de expiración de JWT y la dependencia de Google OAuth2; tener un plan B de autenticación si cambian políticas del proveedor.  
● Observabilidad y pruebas end-to-end: priorizar métricas, logs y trazas en rutas críticas (crear proyecto, invitar/aceptar, solicitud de cambio, login). Esto acelera diagnóstico y protege la experiencia de usuario.  
● Recomendación general: mantener un ciclo de revisión continua entre equipos de producto, frontend y backend usando estas pruebas de aceptación como contrato; así se asegura que las entregas respondan al valor esperado y no sólo a criterios técnicos.
